# 插话纠错（exp/interject）

切换录音（⌥Space）每切出一段，旁路问「说错了没有」，说错了就在刘海上纠正一句（「纠正：苹果是水果」，4 秒）。
不改粘贴、不等它。设计见 vault `Wiki/inkfall-AI插话纠错设计.md`。

- 门：Jev 一次请求问两件事 —— 说完了吗（断句实验的提问，< 0.3 就拼到下一段）/ 有没有可核对的事实断言（< 0.5 不核对）
- 核对：**加工模型**（设置里的 provider / 当前预设那一档的 model / key），另一段提示词（`InterjectionAPI.checkInstructions`），不并进加工。**预设是本地 basic 也照样核对**（第一版要求云端预设，真机上每段停在 `no-check-route`）
- 插不插：`InterjectionPolicy` —— clear_error 且 ≥ 0.8、转写后 5 秒内、同段或后面的话里没改口、同一句不重复、2 分钟冷却
- 日志 `/tmp/inkfall-native.log` 的 `interject:` 行
- 自测：`Inkfall --interject-test "苹果是一种蔬菜" [--previous …] [--provider groq] [--model …]`
- 评测：`python3 experiments/interject/run.py --providers=groq [--model=openai/gpt-oss-120b] [--gated-only]`（先构建 App；加工 key 由 App 自己读钥匙串）

## 评测（2026-09-27，60 条：该插 15 / 正确 15 / 有争议 8 / 观点 8 / 转述 5 / 当场改口 5 / 玩笑 4）

| 判定 | 误插 | 漏插 | 延迟（核对过的） |
|---|---|---|---|
| Jev 单独判「说错了吗」≥ 0.7 | 3 | 0/15 | ~200ms |
| Jev 门 + gpt-oss-20b（加工默认，第 1 次） | 4 | 0/15 | p50 562ms / p90 829ms |
| Jev 门 + gpt-oss-20b（第 2 次，改了 correction 语言要求） | 8 | 0/15 | p50 567ms / p90 733ms |
| 只用 gpt-oss-20b（不过 Jev 门） | 10 | 0/15 | |
| Jev 门 + gpt-oss-120b | 4 | 0/15 | p50 789ms / p90 993ms |

- **该插的 15 条每一种都全中**，更正也像样（「木星是太阳系最大的行星」「盐的化学式是 NaCl」「徳川家康は江戸時代の人物です」）
- **Jev 门有用**：转述别人的话（「我儿子说苹果是蔬菜」claim 0.06）、假设和玩笑大多在门口就挡掉。不过门直接核对，误插 10
- 误插集中在「有争议」和一句玩笑：
  - 冥王星（→ 矮行星）、「最新的 iPhone 是 15」（→ 18）：其实纠正得对，是用例标得保守
  - 花生是坚果（→ 豆类）、番茄 / 香蕉（20b 才出）：看定义的，提示词里写了也挡不住
  - 「薯条是蔬菜，所以我吃的很健康」：两个模型都没听出是玩笑
  - 当场改口（「水50度就开，说错了，100度」）20b 会照样纠正 → 策略里加了同段改口词表，确定性挡掉
- gpt-oss-20b 两次跑同一批，误插 4 → 8，**抖得很厉害**；120b 稳一些，但慢 ~200ms
- Groq 免费档有每分钟限额，评测要 `--pace`；App 里平常说话一段一次，碰不到
- 设置里 Groq 的 `qwen/qwen3-32b` 已经下线（404 model_not_found），加工选它会失败 —— 与本实验无关，另记
